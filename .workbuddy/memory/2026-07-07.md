## Bayer 移动端 — Docker 部署配置适配

- 用户服务器已有 cn-ph-bidding-process 项目，使用路径代理（Nginx）+ Docker Compose 部署
- 本项目需融入同一套部署架构

### 改动

1. **路径代理适配**：前端 base path 设为 `/bayer-mobile/`
   - 新建 `.env` 和 `.env.production`，设置 `VITE_APP_BASE=/bayer-mobile/`
   - `vite.config.ts` 已有 `loadEnv` 支持，无需改代码
   
2. **docker-compose.yml**：`ports` → `expose`，加入 `shared-proxy` 外部网络
   - 不与服务器已有端口冲突，由 Nginx 统一代理

3. **Dockerfile**：dist 拷贝到 `/usr/share/nginx/html/bayer-mobile/`
   - 配合 base path 路径

4. **nginx.conf**：容器内 Nginx 处理 `/bayer-mobile/` SPA 路由

5. **deploy/nginx/reverse-proxy.conf**：服务器 Nginx 要加的 location 片段

6. **DEPLOYMENT.md**：完整部署文档

### 部署流程
1. `docker network create shared-proxy`（一次性）
2. 上传项目到服务器
3. `docker compose up -d --build`
4. 服务器 Nginx 加 location → reload
5. 访问 `http://IP/bayer-mobile/`

### Docker 镜像源问题修复

- Docker 阿里云镜像加速 `rt90zcr4.mirror.aliyuncs.com` 返回 403，导致无法拉取 node:22-alpine 和 nginx:1.27-alpine
- 改用 `Dockerfile.static`（基于 alpine:3.20，本地有缓存），配合 `docker-static-server.sh`（ash nc 简易 HTTP 服务器）
- 改为本地 npm build 后，再用缓存的 alpine 构建镜像，完全无需拉取远程镜像
- 包体 3.8MB，仅需 alpine:3.20 缓存

### 最终文件
- `Dockerfile.static`：COPY dist ./bayer-mobile/，基于 alpine:3.20
- `docker-static-server.sh`：处理 /bayer-mobile/ base path + SPA fallback
- `scripts/package-docker.ps1`：先 npm build，再 docker build -f Dockerfile.static
- `scripts/deploy-docker.sh`：docker run + shared-proxy 网络
- `release/`：已生成可部署包（3.8MB tar）

### 本地打包命令
```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-docker.ps1
```

### 验证结果
- tar → load → run → 全部路由 200 ✓
- 健康检查 healthy ✓ (因 nc 服务器断开连接，wget 改用 grep 判断)
- 包体 3.8MB，无需拉取远程镜像
